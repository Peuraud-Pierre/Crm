# Courbe de tendance « Produits recherchés » (CRM Analytics) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Afficher dans `AnalyticsTab.tsx` une courbe de tendance mensuelle du
nombre total d'entrées « Produits recherchés » (`brief.recherche[]`) sur tous
les clients CRM, alimentée par un snapshot mensuel automatique en base.

**Architecture:** Une fonction SQL `SECURITY DEFINER`, planifiée par
`pg_cron` le 1er de chaque mois, scanne `client_crm.brief` et upsert un total
dans une nouvelle table `crm_produit_recherche_stats`. Le front lit cette
table via un service + hook dédiés (couche obligatoire `CLAUDE.md`), affichés
par un nouveau widget Recharts dans `AnalyticsTab.tsx`.

**Tech Stack:** Supabase (Postgres, RLS, pg_cron), React, Recharts,
`@rstest/core` pour les tests services.

**Spec:** `docs/superpowers/specs/2026-09-03-crm-produit-recherche-trend-design.md`

## Global Constraints

- Aucun appel `supabase.from(...)` direct dans un composant/hook — toujours
  via `services/<ressource>Service.ts` (`CLAUDE.md`).
- Table pas encore dans `src/integrations/supabase/types.ts` (généré) : le
  service utilise un client casté `as unknown as SupabaseClient`, comme
  `briefOptionsService.ts`.
- RLS lecture gatée sur la permission `crm.view` (`public.user_has_permission`).
- Pas de valeurs Tailwind arbitraires ; suivre les tokens `@theme` existants
  (déjà respecté par les widgets copiés en modèle).
- `npm run lint` et `tsc --noEmit` doivent passer sans augmenter le nombre
  d'erreurs existantes avant tout commit.

## Task 1: Migration SQL — table + fonction de snapshot + pg_cron

**Files:**
- Create: `supabase/migrations/20260903090000_crm_produit_recherche_stats.sql`

**Interfaces:**
- Produces: table `public.crm_produit_recherche_stats(id, snapshot_month date UNIQUE, total_entries integer, created_at timestamptz)`, fonction `public.snapshot_produit_recherche_stats() RETURNS void`, job cron `crm-produit-recherche-monthly-snapshot`.

- [ ] **Step 1: Écrire la migration**

```sql
-- ============================================================
-- Courbe de tendance « Produits recherchés » (CRM Analytics)
-- Date: 2026-09-03
--
-- Les entrées brief.recherche[] (client_crm) n'ont pas de date propre :
-- impossible de reconstituer un historique après coup. On enregistre donc
-- une photo mensuelle du total courant, via un job pg_cron, dans une
-- nouvelle table dédiée. Voir
-- docs/superpowers/specs/2026-09-03-crm-produit-recherche-trend-design.md
--
-- Idempotent (guards IF NOT EXISTS / DROP POLICY IF EXISTS / cron.unschedule).
-- ============================================================

BEGIN;

-- ── 1. Table ────────────────────────────────────────────────────────────

CREATE TABLE IF NOT EXISTS public.crm_produit_recherche_stats (
    id             bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    snapshot_month date NOT NULL UNIQUE,
    total_entries  integer NOT NULL,
    created_at     timestamptz NOT NULL DEFAULT now()
);

-- ── 2. RLS : lecture gatée sur crm.view, pas d'écriture applicative ──────

ALTER TABLE public.crm_produit_recherche_stats ENABLE ROW LEVEL SECURITY;

DROP POLICY IF EXISTS "crm.view can read produit recherche stats" ON public.crm_produit_recherche_stats;
CREATE POLICY "crm.view can read produit recherche stats"
    ON public.crm_produit_recherche_stats FOR SELECT
    TO authenticated
    USING (public.user_has_permission(auth.uid(), 'crm.view'));

-- ── 3. Fonction de snapshot ───────────────────────────────────────────────
-- brief peut être un jsonb natif OU une chaîne JSON encodée (cas connu côté
-- front : Client.brief?: FicheAppro | string | null) — on gère les deux.

CREATE OR REPLACE FUNCTION public.snapshot_produit_recherche_stats()
RETURNS void LANGUAGE plpgsql SECURITY DEFINER AS $$
DECLARE
    v_total integer;
BEGIN
    SELECT COALESCE(SUM(jsonb_array_length(parsed.brief_json->'recherche')), 0)
    INTO v_total
    FROM (
        SELECT CASE
            WHEN jsonb_typeof(brief) = 'string' THEN NULLIF(brief#>>'{}', '')::jsonb
            ELSE brief
        END AS brief_json
        FROM public.client_crm
        WHERE brief IS NOT NULL
    ) parsed
    WHERE jsonb_typeof(parsed.brief_json->'recherche') = 'array';

    INSERT INTO public.crm_produit_recherche_stats (snapshot_month, total_entries)
    VALUES (date_trunc('month', now())::date, v_total)
    ON CONFLICT (snapshot_month)
    DO UPDATE SET total_entries = EXCLUDED.total_entries;
END;
$$;

-- ── 4. Planification pg_cron (1er de chaque mois, 02:00 UTC) ─────────────
-- Pattern identique à 20260707150000_arrivage_invoice_reminder_cron.sql.

DO $$
BEGIN
    IF EXISTS (SELECT 1 FROM pg_available_extensions WHERE name = 'pg_cron') THEN
        BEGIN
            CREATE EXTENSION IF NOT EXISTS pg_cron;
        EXCEPTION WHEN OTHERS THEN
            RAISE NOTICE 'pg_cron non installable ici (%).', SQLERRM;
        END;
    END IF;

    IF EXISTS (SELECT 1 FROM pg_extension WHERE extname = 'pg_cron') THEN
        IF EXISTS (SELECT 1 FROM cron.job WHERE jobname = 'crm-produit-recherche-monthly-snapshot') THEN
            PERFORM cron.unschedule('crm-produit-recherche-monthly-snapshot');
        END IF;
        PERFORM cron.schedule(
            'crm-produit-recherche-monthly-snapshot',
            '0 2 1 * *',
            $cmd$ SELECT public.snapshot_produit_recherche_stats(); $cmd$
        );
    END IF;
END $$;

-- ── 5. Backfill immédiat du mois en cours ────────────────────────────────

SELECT public.snapshot_produit_recherche_stats();

COMMIT;
```

```ts
import type { SupabaseClient } from "@supabase/supabase-js"
import { supabase } from "@/integrations/supabase/client"

/**
 * Client Supabase non typé ponctuel pour `crm_produit_recherche_stats` :
 * table pas encore dans `integrations/supabase/types.ts` (fichier
 * auto-généré). Typage applicatif assuré par `ProduitRechercheStatPoint`
 * côté front en attendant.
 *
 * **À régénérer après avoir appliqué la migration** :
 *
 *   npx supabase gen types typescript --project-id <id> \
 *     > src/integrations/supabase/types.ts
 */
const supabaseProduitRecherche = supabase as unknown as SupabaseClient

export interface ProduitRechercheStatPoint {
    month: string
    total: number
}

export async function listProduitRechercheStats(): Promise<
    ProduitRechercheStatPoint[]
> {
    const { data, error } = await supabaseProduitRecherche
        .from("crm_produit_recherche_stats")
        .select("snapshot_month, total_entries")
        .order("snapshot_month", { ascending: true })
    if (error) throw error
    return (
        (data as { snapshot_month: string; total_entries: number }[]) || []
    ).map((row) => ({ month: row.snapshot_month, total: row.total_entries }))
}
```

- [ ] **Step 1: Implémenter le hook**

```ts
import { useEffect, useState } from "react"
import * as produitRechercheStatsService from "@/features/crm/services/produitRechercheStatsService"
import type { ProduitRechercheStatPoint } from "@/features/crm/services/produitRechercheStatsService"

export function useProduitRechercheStats() {
    const [data, setData] = useState<ProduitRechercheStatPoint[]>([])
    const [loading, setLoading] = useState(true)

    useEffect(() => {
        let cancelled = false
        setLoading(true)
        produitRechercheStatsService
            .listProduitRechercheStats()
            .then((points) => {
                if (!cancelled) setData(points)
            })
            .catch(() => {
                // silent — le widget affiche l'état vide si data reste []
            })
            .finally(() => {
                if (!cancelled) setLoading(false)
            })
        return () => {
            cancelled = true
        }
    }, [])

    return { data, loading }
}
```
